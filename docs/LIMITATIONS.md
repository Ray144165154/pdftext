# 已知限制

这份文档把"`pdftext` 做不到什么"写清楚。知道边界在哪里，比假装没有边界有用。

---

## 不支持（会明确报错或跳过，不会静默出错）

### 1. 加密 PDF

带 `/Encrypt` 的文件会在打开时抛 `DocumentError`，不会给出半截乱码。

```
该 PDF 已加密（/Encrypt）。本工具不实现解密，请先用 qpdf --decrypt 处理。
```

想支持的话，标准安全处理器（RC4 / AES-128 / AES-256）需要实现
PDF 32000-1 的 7.6 节，包括密钥派生与权限校验——这是一个独立项目的工作量。

**绕过办法**：先用 `qpdf --decrypt 输入.pdf 输出.pdf` 解密再提取。

### 2. 扫描件（没有文本层）

扫描件是图片，里面根本没有文字对象。`pdftext` 不做 OCR。

`--stats` 会明确提示你这一点：

```
字符数: 0
含文本层的页: 0/3
提示: 没有任何文本层，这多半是扫描件（纯图片），需要 OCR 才能取字。
```

**绕过办法**：用 Tesseract 之类的 OCR 工具，或者用带 OCR 文字层的 PDF
（那种 PDF 的文字渲染模式是 3 = 不可见，`pdftext` 会把它们正常提取出来）。

### 3. 竖排文字（`Identity-V`）

竖排 PDF 的字符前进方向是向下的。`pdftext` 会正确取出字，但**按横排的方式
重排行**，所以竖排诗词、竖排表格的顺序会不对。

判定方法是看字体的编码是否为 `Identity-V`——目前代码没有区分。

### 4. 阅读顺序来自坐标，而不是结构树

带标签的 PDF（Tagged PDF）里有 `/StructTreeRoot`，记录了作者定义的逻辑阅读顺序
（对多栏排版、侧栏、脚注尤其重要）。

`pdftext` **完全忽略结构树**，阅读顺序是按坐标聚类推断出来的。
后果：**多栏排版的学术论文，两栏文字会被按 y 坐标交错合并**。

如果你需要正确的分栏阅读顺序，用 `pdfminer.six` 或 `pdfplumber`。

### 5. 表格结构

`--layout` 只是按 x 坐标近似对齐列，**不识别表格边界**，
也不会输出 CSV/HTML。

需要真正的表格提取用 `pdfplumber` 或 `camelot`。

### 6. 其他

| 项目 | 说明 |
|---|---|
| 文本渲染模式 | 会记录 `render_mode`，但不据此过滤。模式 3（不可见）的文字也会被提取——这通常是你想要的 |
| `Type3` 字体 | 能取到码与文字，字形宽度来自 `/Widths`；不执行字形的 charproc |
| 嵌入字体的 `.notdef` | 没有 ToUnicode 又没有编码表兜底时，该码位会被跳过（不输出 □） |
| CMap 里未映射的码 | 同上，跳过而不是猜 |
| `/ActualText` 替换 | 不支持替换文本（用于连字、变体选择符） |
| 颜色 | 记录 RGB 近似值；CMYK 会粗略转 RGB，专色不解析 |
| 图元 | 完全不解析路径、图片、注释、表单域 |

## 已知的弱点（能用，但不够好）

### 性能

纯 Python，单页约 **3.5 ms**（简单页面，Python 3.12）。复杂页面（大量
Form XObject、上万字符）会明显更慢。

比 `PyMuPDF`（C 实现）慢一到两个数量级是必然的。这是"零依赖 + 可读"
换来的代价，是有意识的取舍。

### 空格判定是启发式的

`layout.py` 里两个常量决定一切：

```python
_LINE_TOLERANCE_RATIO = 0.35   # 行聚类：基线差 < 0.35 × 字号 视为同一行
_SPACE_RATIO = 0.28            # 插空格：实际位置超出预期 > 0.28 × 字号
```

这套参数在正文、表格、中文混排上表现良好，但**没有任何参数能在所有 PDF 上都对**。
极端情况：

- 艺术字/海报里字距被刻意拉开很大 → 会多出空格
- 极小字号 (< 4pt) 下 0.6pt 的下限可能不够
- 字符间距为负（字挤在一起）→ 不会合并字符

遇到问题时，你可以直接改这两个常量，或者绕开 `layout` 层自己用
`page.chars` 的坐标做后处理。

### 行聚类对旋转文本不友好

如果整页文字都旋转了（比如横向打印的图表标题），行聚类仍然按 y 排序，
结果可能不合预期。页面级的 `/Rotate` 是正确处理了的，
但**内容流内部用 `Tm` 自己旋转的文字**没有特殊处理。

### 交叉引用重建可能漏对象

当 xref 损坏时，`pdftext` 会全文件扫描 `N G obj` 重建。这个兜底很有用
（真实世界的 PDF 经常是坏的），但：

- 文件被**截断**时，物理上不存在的内容救不回来
- 重建后的 `doc.repaired` 是 `True`，CLI 会往 stderr 打一条提示
- 极端畸形文件可能扫出错误的对象边界

### 单个操作符出错会被跳过

`content.py` 执行操作符时用了宽泛的 `except Exception: pass`。
这样**一个坏操作符不会毁掉整页**，但代价是错误会被静默吞掉。

如果你在排查"为什么某段文字没出来"，可以在
`ContentInterpreter._execute` 的调用处临时改成让异常抛出。

## 与规范的偏差

`pdftext` 实现的是 PDF 文本提取**需要的子集**，不是完整实现。明确没做的：

- 线性化（Linearized PDF）的提示区不解析——不影响正确性，只是没利用它加速
- `/Filter` 链里的 `Crypt` 过滤器不实现
- 字体 `/Widths` 缺失时用 `/MissingWidth`，再缺失则用 500（规范建议的常见值），
  这是一种猜测，可能导致空格判定偏差
- `TJ` 的调整量、`Tc`/`Tw` 都按规范计算，但**不模拟字体的 hinting 影响**

## 发现新问题？

欢迎提 [Issue](https://github.com/Ray144165154/pdftext/issues)。

**请不要上传受版权保护的 PDF。** 用 `tests/pdfbuilder.py` 造一个最小复现样本
（几十行代码就能构造出触发条件），这样既没有版权问题，也更容易定位。
